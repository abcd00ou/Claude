# AI 공급망 GEM 개발 로드맵

**문서 유형:** 개발 로드맵 · **최종 수정:** 2026-07-06
**엔진 위치:** `agents/data/dba/` · **데이터:** `panel_long`

---

## 0. 비전

AI 반도체 공급망에 특화된 **소규모 Global Economic Model(GEM)**. Oxford Economics
GEM의 *정신*(연결된 방정식 시스템 + 회계 항등식 + 시나리오 시뮬레이션)을 거시 국가
단위가 아니라 **AI 공급망 섹션 단위**로 이식한다. 목표는 예측기가 아니라 **"충격이
공급망을 어떻게 타고 흐르는지"를 내적으로 일관되게 시뮬레이션하는 시스템**이다.

> 핵심 원칙: lead-lag 매트릭스는 GEM의 **설계도**이지 GEM이 아니다. 매트릭스로 방정식을
> 특정화하고, 그것을 **연립 시스템으로 추정**하고, **항등식으로 닫아야** GEM이 된다.

## 2. 아키텍처 원칙

1. **단일 데이터 레이어** — 모든 것은 `panel_long`(ticker·companyname·date·item·value·section)에서 나온다. 전처리(`build_panel_long.py`)와 분석은 분리.
2. **지표는 함수로** — 파생변수는 저장하지 않고 `features.py`가 필요할 때 계산(38종 + 변환).
3. **관계는 명시적** — 고객-공급사 방향은 사전지식(밸류체인)으로 고정, 통계는 그 안에서 검증.
4. **행동방정식 + 항등식** — 추정할 것과 정의할 것을 구분해 시스템을 닫는다.
5. **작게, 그러나 일관되게** — 40분기 제약상 소규모 시스템. 모든 방정식이 동시에 성립.

## 3. 5단계 개발 로드맵

각 단계: **목표 · 입력 · 방법 · 산출물 · 완료기준 · 현재상태 · 리스크**

### Step 0 — 데이터·지표 레이어 ✅ 완료
- **목표:** 분석 가능한 단일 롱테이블 + 파생지표 엔진
- **산출물:** `panel_long`(19 items, 121사, 2016–2027, payables 포함), `features.py`(38 지표), `panel.py`
- **완료기준:** DIO/DSO/DPO/CCC·마진·성장·spread 전부 계산 ✔

### Step 1 — Lead-Lag 매트릭스 (스크리닝) ✅ 완료
- **목표:** 전체 지표×지표 선후행 지도 → 방정식 후보 발굴
- **입력:** `features` 38지표 · **방법:** 모든 X×Y 쌍 시차상관(0~4q), Pearson+Spearman, 유의성·|상관|·시차 랭킹
- **산출물:** `leadlag_matrix.py`, `leadlag_matrix_internal.csv`, `leadlag_matrix_cross.csv`, `equation_candidates()`
- **완료기준:** 각 핵심 내생변수 Y별 상위 선행 X 후보 추출 가능 ✔
- **리스크:** lag=0 항등식 관계(CCC↔DIO 등)가 상위 점유 → `min_lag≥1` + 이론필터로 제거

### Step 2 — 방정식 특정화 ⏭ 다음
- **목표:** 각 내생변수의 행동방정식 형태 확정
- **입력:** Step 1 매트릭스 + 밸류체인 사전지식 + 기대부호(가이드 문서)
- **방법:** 내생변수 Y(예: 섹션 매출성장, OCF_MARGIN, CCC)마다 (a) 자명한 항등식·lag0 제거, (b) 유의·기대부호 일치·시차안정 X만 우변 채택, (c) 변수당 우변 4~5개 상한
- **산출물:** `equations.py` — 방정식 명세(좌변 Y, 우변 X·시차·기대부호) 레지스트리
- **완료기준:** 6~10개 방정식이 이론+통계로 정당화되어 명세화
- **리스크:** 과적합(우변 과다), 다중공선성 → VIF 점검·축소

### Step 3 — 연립 시스템 추정 ⏳ 핵심
- **목표:** 방정식들을 **하나의 시스템**으로 추정(쌍별 → 시스템 승격)
- **방법:** (a) 소규모 **VECM**(공적분 벡터 + 조정행렬, Johansen 근사) 또는 (b) **SUR/3SLS**(동시성 처리). 표본 제약 시 **베이지안 VAR(사전분포)**
- **산출물:** `gem_system.py` — 계수행렬·공적분관계·조정속도
- **완료기준:** 시스템이 수렴·안정(고유값<1), 잔차 백색잡음에 근접
- **리스크:** 40분기로 다변량 추정 자유도 부족 → 변수 최소화·BVAR·블록 분해

### Step 4 — 항등식 Closure ⏳
- **목표:** 행동방정식 + 회계 항등식으로 **완결(closed) 시스템** 구성
- **방법:** `FCF=OCF−capex`, `CCC=DIO+DSO−DPO`, `OCF_MARGIN=OCF/revenue`, 공급망 `고객 COGS ≈ Σ공급사 매출`(근사 항등식)로 내생변수 연결
- **산출물:** 항등식 그래프 + 완결 시스템 정의
- **완료기준:** 모든 내생변수가 방정식 또는 항등식으로 결정(자유변수=외생만)

### Step 5 — 시뮬레이션·시나리오 엔진 + 검증 ⏳
- **목표:** 충격→전체 시스템 반응 시뮬레이션(진짜 GEM 기능) + 타당성 검증
- **방법:** baseline 경로 → 충격 시나리오(예: 하이퍼스케일러 capex +20%) → 전 섹션 IRF. 동적 시뮬레이션(항등식+방정식 반복)
- **산출물:** `gem_simulate.py`, 시나리오 리포트, 대화형 노트북
- **완료기준(검증):** ①in-sample RMSE 합리적 ②out-of-sample(마지막 4~8분기 홀드아웃) 예측 ③충격반응 부호·안정성이 경제이론과 일치

---

## 4. 표본 제약(≈40분기)과 대응 — 가장 중요한 현실

| 문제 | 대응 |
|---|---|
| 다변량 추정 자유도 부족 | 시스템을 **6~10 방정식**으로 제한, 변수당 우변 ≤5 |
| 과적합 | **베이지안 VAR**(Minnesota prior), 정규화 |
| 약한 식별 | **사전정보 주입**: 밸류체인 방향·기대부호를 제약으로 |
| 공적분 검정력 낮음 | θ 유의성+λ 부호를 함께 보고 신뢰도 등급화(과신 금지) |
| 2020–26 구조변화(AI붐) | 롤링 추정·체제전환 점검, 필요시 더미 |

> **역설:** lead-lag는 *전부* 스캔(스크리닝)하되, 시스템에는 *소수 정예*만 넣는다.
> 전부 파악하는 이유는 무엇을 버릴지 알기 위해서다.

---

## 5. 검증 프로토콜 (Step 5 상세)

1. **In-sample:** 방정식별 R²·RMSE, 잔차 자기상관(Ljung-Box 근사)
2. **Out-of-sample:** 마지막 4~8분기 홀드아웃, 1~4분기 앞 예측오차
3. **충격반응:** IRF 부호·크기가 밸류체인 이론과 일치하는지, 발산하지 않는지
4. **역사적 시나리오:** 알려진 사건(2022 메모리 다운턴, 2023 AI 급등) 재현 여부

---

## 6. 확장 경로 (GEM 성숙도 ↑)

- **거시 연결:** FRED에서 글로벌 GDP·정책금리·데이터센터 capex 지수를 **외생 드라이버**로 상류에 결합 → "거시→AI산업" 전달경로
- **다중 공적분:** Engle-Granger(단일) → **Johansen VECM**(시스템 공적분)
- **고빈도 보강:** 분기 재무 + 주가(주간)로 nowcasting
- **기업 단위 하위모형:** 섹션(집계) → 개별 기업(각국 내 지역처럼)
