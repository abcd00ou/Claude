## A. 실습 자료

### 상황
고객사에 들어가기 전에 FDE 본인이 먼저 AI 빌더가 되어야 합니다. 상품기획팀의 반복 업무 3개를 케이스 데이터로 미리 자동화해 봅니다. 이번 주 결과물은 **나중에 고객 환경에 그대로 옮길 부품**입니다.

### 작업 환경 세팅 (첫날)
- 범용 코딩 에이전트 1개 (Claude Code, Codex 등 중 하나)
- 세션 유지 환경 (tmux 또는 그에 준하는 도구)
- 작업 폴더 구조
  ```
  fde-daesung/
  ├── AGENTS.md (또는 CLAUDE.md)   ← 프로젝트 공통 지침
  ├── skills/                      ← 업무별 스킬
  ├── data/                        ← case/data 복사본
  └── out/                         ← 산출물
  ```
- **AX 타임:** 매일 2시간은 엑셀이나 문서 도구를 직접 열지 않습니다. 10분 단위로 진행 상황을 스레드에 남깁니다.

### 과제: 자동화 3건
1. **VOC 정제 스킬:** `voc_raw.csv` → 정규화된 VOC 테이블
   - 날짜 통일, 고객명 정규화, 7개 분류
2. **경쟁사 비교표 스킬:** `competitor_specs.csv` → 750W급 비교표
   - 출처 신뢰도 표시
3. **주간 영업 하이라이트 스킬:** `crm_notes.csv` → 주간 하이라이트 1쪽

### 제약
- 아직 고객 인터뷰 전입니다. 상품기획팀의 내부 규칙(암묵지)은 모르는 상태로 만듭니다. **모르는 부분은 "가정"으로 명시합니다.**
- 동시 세션은 최대 3개까지만 돌립니다. 각 세션의 결과를 직접 검수한 기록을 남깁니다.

### 제출 양식
```
2-1_환경세팅.md          (도구, 폴더, 공통 지침 전문)
2-2_skills/voc_clean.md, competitor_table.md, weekly_highlight.md
2-3_자동화보고서.md      (전후 비교, 가정 목록, 검수 기록, "업무가 정말 없어졌나" 판정)
```

### 평가 포인트
- 스킬이 **지침 파일** 형태인가. 업무마다 별도 프로그램을 짜지 않았는가 (3주차와 연결).
- 가정을 명시했는가. 이 가정들이 6주차에 암묵지로 교정되는 것이 이 과정의 빌드업입니다.
- 검수 기록이 있는가 (07-14 영상: 검수 가능한 단위로 쪼개기).

## B. 예상 산출물

### 2-1. 공통 지침 (AGENTS.md) 예시
```markdown
# 대성모션 상품기획 작업 지침 (v0.1, 2026-W2, 가정 기반)
- 언어: 한국어. 결과는 out/ 아래 날짜별 폴더에 저장한다.
- 원본 data/는 수정하지 않는다. 가공본은 out/에 쓴다.
- 숫자를 쓸 때는 반드시 출처 파일과 기간을 함께 적는다.
- 모르는 규칙은 지어내지 말고 "가정:"으로 표시한 뒤 보고서 끝에 모은다.
- 단가, 할인율이 담긴 컬럼은 요약에 쓰지 않는다. (보안 등급 미확인, 보수적으로 처리)
```

### 2-2. 스킬 예시: `skills/voc_clean.md`
```markdown
# VOC 정제 스킬 (v0.1)
입력: data/voc_raw.csv
출력: out/voc_clean.csv
       컬럼: 접수일(YYYY-MM-DD), 고객_정규화, 담당영업, 채널, 내용, 분류, 중복여부

1. 날짜: "6/3", "2026.6.3", "26년 6월 3일"을 모두 2026-06-03 형식으로 바꾼다.
2. 고객명: 별칭 사전으로 정규화한다.
   누리로봇, (주)누리로보틱스, Nuri → 누리로보틱스
   세온로보, SEON → 세온
   ARKBOT, 아크봇(주) → 아크봇
   동진 → 동진기계 / 한일PKG → 한일패키징 / 성우 → 성우자동화
   대명에프에이 → 대명FA / Greentech → 그린텍
3. 분류: 신규요구, 성능, SW·튜닝, 가격, 품질, 납기, 기술지원 중 하나. 원본 분류 칸은 신뢰하지 않는다.
4. 중복: 같은 날, 같은 고객, 같은 내용이면 중복으로 표시한다.
   가정: 날짜가 다른 같은 내용은 별건으로 본다. → 고객 확인 필요
5. 끝에 분류별 건수와 가정 목록을 출력한다.
```

### 2-3. 자동화 보고서 (핵심 수치)

**VOC 정제 (가정 기반 v0.1 결과)**

| 항목 | 값 |
|---|---|
| 원본 행 수 | 56 |
| 완전 중복(같은 날, 같은 고객, 같은 내용) 제거 | 5건 제거 → 51건 |
| 분류별 건수 | 7개 분류로 배정. 아래 참고 |

- v0.1 규칙은 날짜가 다른 반복 제기를 별건으로 셉니다. 그래서 정답 키(37건)보다 많은 51건이 남습니다.
- **이 차이가 6주차에 K8("같은 고객의 같은 이슈 반복은 1건")로 교정됩니다.** 수강생 결과가 51건 근처이면 정상입니다.
- 이번 주에는 7개 분류를 모두 포함합니다. 납기와 품질을 리포트에서 빼는 규칙(K3)은 아직 모르는 단계이고, 4~6주차에 발견합니다.

**가정 목록 (모범 답안에 반드시 있어야 할 것)**
1. 날짜가 다른 같은 내용은 별건으로 본다.
2. 모든 분류를 상품기획 리포트에 포함한다.
3. 모든 고객의 요청을 같은 가중치로 센다.
4. 경쟁사 비교는 카탈로그 최대 토크 기준이다. **(틀린 가정이며, 6주차 K7로 교정됩니다)**

**경쟁사 비교표 v0.1 (카탈로그 기준)**

| 모델 | 최대 토크 (Nm) | 가격 (천원) | 납기 (주) | 출처 |
|---|---|---|---|---|
| 대성 DX5-750 | 7.16 | 1,180 | 10 | 데이터시트 |
| 미라텍 MR-A750 | **7.5** | 1,090 | 6 | 카탈로그 |
| 한결 HG-750S | 7.2 | 1,120 | 7 | 데이터시트 |

- 이 표만 보면 "미라텍이 토크가 높고 더 싸다"는 결론이 나옵니다.
- 6주차 재작업에서 연속 토크로 비교하면 **대성 2.39 vs 미라텍 2.25**로 결론이 뒤집힙니다. 이것이 빌드업 포인트입니다.

**주간 하이라이트 v0.1 (요지)**
- 로봇 OEM 3사(아크봇, 세온, 누리로보틱스)가 일체형 또는 중공축을 반복해서 요구합니다. 세온 RFQ 마감은 7월 31일로 연장되었습니다.
- 누리로보틱스가 DX5-750 연 2,400대 LOI를 검토 중입니다. 20% 할인과 8주 납기를 요구합니다.
- DS3-100은 대리점 재고 340대가 있고, Zhenli 저가 공세를 받고 있습니다. 단종 루머 문의가 있습니다.
- 할인 기준이 영업 메모(12%)와 상품기획 기준(15%)에서 다르게 나옵니다. 확인이 필요합니다.

**"업무가 정말 없어졌나" 판정**

| 업무 | 판정 |
|---|---|
| VOC 정제 | 부분적으로만. 규칙 미확정 때문에 사람이 검수해야 합니다 |
| 경쟁사 비교 | 아니오. 비교 기준을 확인해야 합니다 |
| 주간 하이라이트 | 예. 초안 생성은 대체되었습니다 |

→ **결론:** 고객의 암묵지 없이는 비가역적 자동화가 불가능합니다. 이것이 4~6주차의 존재 이유입니다.
