- **넘기는 것:** 아키텍처 설계서 v1과 데이터 등급 매트릭스 → 4주차 정해린 책임 인터뷰의 준비물이자 5주차 SOW의 기술 부분

## A. 실습 자료

### 상황
RFP는 "에이전트 5종"을 요구합니다. 여러분은 이를 **범용 에이전트 1개 + 스킬 + 데이터 채널 + 거버넌스** 구조로 다시 설계해서, 4주차 첫 미팅에 가져갑니다.

### 과제
1. **매핑:** RFP 에이전트 5종을 "범용 에이전트가 수행할 스킬"로 다시 매핑합니다. 2주차에 만든 스킬 3개를 재사용합니다.
2. **데이터 등급 매트릭스 초안:** 데이터 6종 각각에 대해 다음을 추정합니다.
   - 보안 등급 가설
   - 에이전트에 넣을 수 있는 형태
   - 데이터 소유자
3. **거버넌스 초안**
   - 누가 스킬과 지침을 바꿀 수 있는가
   - 변경은 어떻게 검토하는가
   - 로그는 어떻게 남기는가
4. **유지보수 시나리오:** 2027년 1월에 "VOC 분류에 '안전·인증'이 추가된다"고 가정합니다. RFP 방식과 우리 방식의 수정 범위를 비교합니다.

### 제출 양식
```
3-1_아키텍처설계서_v1.md
3-2_데이터등급매트릭스_v0.md
3-3_유지보수시나리오.md
```

### 평가 포인트
- 개별 에이전트 개발이 0건인가 (07-06).
- 단가와 할인이 담긴 데이터를 별도 등급으로 분리했는가 (7주차 이벤트를 미리 대비).
- 기업이 쥐어야 할 것을 "에이전트"가 아니라 "데이터 채널과 지침·컨텍스트"로 정의했는가.

## B. 예상 산출물

### 3-1. 아키텍처 설계서 v1 (요지)

**구조**
```
[사내 승인 범용 에이전트 1개]  ← 상품기획팀 전원이 같은 환경을 사용
   │
   ├─ 공통 지침 (AGENTS.md): 회사·팀 규칙, 보고 스타일
   ├─ 스킬 (skills/*.md): 업무별 절차
   ├─ 컨텍스트 그래프 (knowledge/): 암묵지, 용어집, 출처 태그  ← 6주차에 구축
   └─ 데이터 채널 (등급별)
        ├─ 일반:        경쟁사 공개 스펙, 전시회 리드, 집계 실적
        ├─ 내부:        VOC (할인 조건 마스킹 후)
        └─ 대외비 A:    단가, 고객별 할인 → 에이전트에 원본 투입 금지. 집계 결과만 사용
```

**RFP 5종 → 스킬 매핑**

| RFP 요청 | 우리 방식 | 상태 |
|---|---|---|
| ① VOC 자동 분류 에이전트 | `voc_clean` 스킬 | 2주차 v0.1 존재 |
| ② 경쟁사 동향 모니터링 에이전트 | `competitor_table` 스킬 + 주간 실행 | 2주차 v0.1 존재 |
| ③ 월간 리포트 자동 작성 에이전트 | `monthly_report` 스킬 (①②의 출력과 보고 스타일 지침을 조합) | 7주차 |
| ④ 가격 시뮬레이션 에이전트 | `price_review` 스킬 (대외비 데이터는 집계 결과만 사용) | 캡스톤 |
| ⑤ 신제품 기획서 초안 에이전트 | `prd_draft` 스킬 | 캡스톤 (DX-7) |

**기업이 쥐는 것:** 데이터 채널, 공통 지침, 스킬, 컨텍스트 그래프. 모두 텍스트와 데이터이며 고객사 소유입니다. 범용 에이전트 제품이 바뀌어도 그대로 옮길 수 있습니다.

### 3-3. 유지보수 시나리오: "안전·인증" 분류 추가

| | RFP 방식 (에이전트 5종) | 우리 방식 |
|---|---|---|
| 수정 대상 | VOC 분류 에이전트의 코드와 프롬프트, 월간 리포트 에이전트, 대시보드 | `voc_clean.md`의 분류 목록 1줄, 컨텍스트 그래프의 분류 정의 1개 |
| 누가 하나 | 외주 유지보수 업체 (변경 요청 → 견적 → 개발) | 고객사 메인테이너가 지식 PR로 수정 → 팀장이 승인 |
| 소요 | 수 주 | 하루 이내 |
| 위험 | 외주 계약이 끝나면 방치됨 | 지식 PR 검토자가 없으면 품질 저하 → 8주차 인수 계획으로 대응 |
