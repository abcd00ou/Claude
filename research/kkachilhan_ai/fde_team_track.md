# 팀 과제 랩 설계안: B2B 영업, 마케팅, 상품기획 × Codex

- **작성일:** 2026-11-23 (설계안, 확인 전)
- **상위 문서:** [fde_curriculum.md](fde_curriculum.md) (12주 FDE 과정), [fde_lab/README.md](fde_lab/README.md) (대성모션 케이스)
- **들어갈 곳:** `research/ai-work-lab` 웹사이트. "빠른 시작" 튜토리얼을 마친 뒤 이어지는 단계
- **근거:** 방법론은 유튜브 '까칠한 AI' 영상(날짜 표기)에서 가져왔습니다. 회사, 인물, 데이터는 기존 FDE 랩의 **가상 회사 대성모션** 자료를 그대로 씁니다.

## 1. 무엇을 바꾸나

| | 기존 FDE 양성 과정 | 팀 과제 랩 (이번 설계) |
|---|---|---|
| 대상 | 고객사에 들어가는 외부 FDE | **현업 직원** (영업, 마케팅, 상품기획) |
| 관점 | FDE가 고객 조직을 바꾼다 | **내가 내 팀 업무를 AI로 바꾼다** (꼭짓점 AX, 03-17 / 리서처 모드, 11-02) |
| 기간 | 12주 | 팀별 미션 4개 (미션당 30~60분) + 공통 캡스톤 1개 |
| 도구 | 범용 에이전트 일반 | **Codex** (빠른 시작에서 설치한 환경 그대로) |
| 결과 확인 | 강사 평가 | 웹에서 **숫자 정답 자동 확인** + 자기 점검 체크리스트 + 모범 답안 |

FDE 과정의 원칙 중 현업에게도 그대로 필요한 다섯 가지를 모든 미션에 넣습니다.

1. **요청을 그대로 때려박지 않는다.** 먼저 계획과 접근 방식을 받는다 (11-02)
2. **원본은 건드리지 않는다.** 되돌릴 수 없는 행동(발송, 덮어쓰기)은 사람이 승인한다 (02-27)
3. **팀의 암묵지를 규칙으로 적는다.** 엑셀 매크로와 시니어의 머릿속에 있는 기준을 Codex에 알려 준다 (03-05, 04-09)
4. **숫자는 검증한다.** 결과의 행 수, 합계, 기준 위반 건수를 직접 확인한다
5. **데이터 등급을 지킨다.** 원가, 단가 같은 대외비는 외부로 보내지 않는다 (케이스의 정해린 책임)

   팀 선택 ──┬── A. B2B 영업팀   (윤태호 차장, 최은재 차장)

## 3. 공통 미션 0: 우리 팀 업무 지도 (20분)

- **상황:** 본부장이 "AI로 뭘 할 수 있는지 각 팀이 1장으로 가져오라"고 했습니다.
- **할 일:** 반복 업무 5개를 적고, 주기, 걸리는 시간, 사용하는 데이터, 실수했을 때 되돌릴 수 있는지를 표로 만듭니다. Codex에게 "맡길 것 / 사람이 승인할 것 / 맡기지 않을 것"으로 나누게 하고, 그 이유를 받습니다.
- **산출물:** `업무지도.md`
- **자기 점검:** 고객에게 나가는 일(발송, 견적 확정)을 '맡길 것'에 넣지 않았는가?

## 4. 팀별 미션

각 미션은 같은 틀로 구성합니다: **상황(인물 대사) → 자료 → 목표 → 프롬프트 뼈대(목표·입력·출력·제약·검증 빈칸) → 단계별 힌트 → 정답 확인 → 모범 답안 → 회고 질문**

### A. B2B 영업팀

| # | 미션 | 쓰는 자료 | 배우는 원칙 | 정답 확인 |
|---|---|---|---|---|
| A1 | **고객 이름 정리와 고객별 매출 집계.** ARKBOT, 아크봇, (주)아크봇처럼 다르게 적힌 고객명을 하나로 묶고 고객 단위로 다시 센다 | VOC, CRM 메모, 전시회 리드 | 건수가 아니라 **고유 회사 단위** (11-02 리서치 브리프) | 고유 고객 수 |
| A2 | **특판가 요청 검토표.** CRM 메모의 할인 요청을 현행 기준(일반 15%, 로봇 OEM은 LOI와 전무 승인 시 20%)에 대조해 승인 가능 / 승인 필요 / 불가로 나누고 마진을 계산 | CRM 메모, 가격표 | 팀마다 다른 기준(영업 12% vs 상품기획 15%) = **암묵지 충돌** 찾기 | 기준 초과 건수 |
| A3 | **고객 미팅 1쪽 브리프.** 아크봇 미팅 전에 CRM, VOC, 리드에서 이 고객 이야기만 모아 요약. 모든 문장에 출처 행 표시 | CRM, VOC, 리드 | 출처 없는 문장 금지, **리서치 먼저** | 자기 점검 (출처 누락 0) |
| A4 | **영업 메모 정리 스킬.** 아무렇게나 쓴 메모를 붙여넣으면 고객, 제품, 요청, 다음 행동, 기한으로 정리하는 재사용 지시문(스킬)을 만든다 | 직접 쓴 메모 3개 | 반복 업무는 **스킬 1개로** (07-06 범용 에이전트) | 자기 점검 |

### B. 마케팅팀

| # | 미션 | 쓰는 자료 | 배우는 원칙 | 정답 확인 |
|---|---|---|---|---|
| B1 | **전시회 리드 우선순위.** 행동(견적 요청 > 샘플 요청 > 방문)과 업종 적합도로 점수를 매기고 영업 담당을 배정 | 전시회 리드 16건 | 점수 기준을 **먼저 합의**하고 실행 | A등급 리드 수 |
| B2 | **경쟁 비교표 다시 만들기.** 카탈로그 최대 토크와 데이터시트 연속 토크를 구분하고 출처 신뢰도를 표시 | 경쟁 스펙 | 시니어 기준 K7: **결론이 뒤집힌다** (미라텍 MR-A750) | 연속 토크 기준 비교 결과 |
| B3 | **고객 언어 메시지 3개.** VOC에서 고객이 실제로 쓴 말로 핵심 메시지 3개와 근거 VOC를 뽑는다 | VOC | 상상한 메시지가 아니라 **근거 있는 메시지** | 자기 점검 (근거 행 3개 이상) |
| B4 | **후속 이메일 초안 생성기.** 리드별 맞춤 이메일 초안을 만들되, 발송은 하지 않고 검토 목록으로만 만든다 | 리드, VOC | **비가역 행동은 사람 승인** (02-27) | 자기 점검 (발송 코드 없음) |

### C. 상품기획팀

| # | 미션 | 쓰는 자료 | 배우는 원칙 | 정답 확인 |
|---|---|---|---|---|
| C1 | **VOC 정리.** 날짜 형식과 고객명 표기를 통일하고 "같은 고객의 같은 이슈는 1건" 규칙으로 중복 제거 | VOC 원본 56행 | 매크로에 숨은 규칙 K8을 **명시적 규칙**으로 | 정리 후 37건 |
| C2 | **제품군 수익성 대시보드.** 12개월 판매 데이터로 제품군, 고객 유형별 매출과 마진 추이를 HTML 1장으로 | 판매 실적 480행 | 숫자 검증 (합계 대조) | 2026년 상반기 합계 32,083백만 원 |
| C3 | **DX-7 리서치 브리프.** 일체형, 중공축, 외경 80mm 요구 신호를 모으고 접근 방식 A/B/C를 비교 | VOC, CRM, 리드, 경쟁 스펙 | **인텐트 때려박기 금지**, 접근 방식부터 (11-02) | 자기 점검 + 모범 답안 |
| C4 | **월간 리포트 자동화.** VOC와 판매 데이터를 넣으면 본부장용 1쪽 리포트(판단 근거 포함)가 나오는 절차를 만든다 | C1, C2 결과 | **버티컬 AX**: 결정에 바로 쓰이는 산출물 (06-11) | 자기 점검 |

정답 수치는 기존 랩의 강사용 정답(`fde_lab/instructor/`)과 데이터 파일에서 다시 계산해 확정합니다. 웹에 넣기 전에 직접 계산해 맞춰 보겠습니다.

## 5. 공통 캡스톤: DX-7 Go/No-go (60분)

- **상황:** 강도윤 전무가 "다음 분기 회의에서 DX-7 개발을 시작할지 결정하겠다"고 합니다.
- **할 일:** 자기 팀 산출물(A1 고객 단위 수요, B2 경쟁 비교, C3 리서치 브리프 등)을 모아 1쪽 결정 메모를 씁니다. 다른 팀 미션을 하지 않았다면 모범 답안을 가져다 씁니다.
- **메모 형식:** 권고(Go / No-go / 조건부) → 근거 3개(출처 포함) → 리스크 → 결정 전에 확인할 질문
- **자기 점검:** 숫자마다 어느 파일의 몇 행에서 나왔는지 따라갈 수 있는가?

## 6. 웹 기능 (ai-work-lab에 추가)

| 기능 | 내용 |
|---|---|
| 팀 선택 | 빠른 시작 마지막 단계와 대시보드에서 진입. 인물 카드 3장 |
| 미션 화면 | 상황 → 자료 → 목표 → 프롬프트 뼈대 → 힌트(단계별로 열기) → 정답 확인 → 모범 답안 → 회고 |
| 자료 받기 | ① **"파일 만들기" 프롬프트 복사**: CSV 내용을 담은 지시문을 Codex에 붙여넣으면 연습 폴더에 파일이 생깁니다 ② 사내 서버나 Vercel에 배포했을 때는 ZIP 다운로드도 제공 (Claude 페이지에서는 다운로드가 막혀 있어 ①만 동작) |
| 정답 확인 | 숫자를 입력하면 맞음 / 다시 확인으로 답합니다. 틀리면 흔한 실수 힌트를 보여 줍니다 (예: 56 → 중복 제거 안 함, 51 → 고객명 통일 안 함) |
| 모범 답안 | 정답 확인을 한 번 하거나 "포기하고 보기"를 눌러야 열립니다 |
| 진행률 | 팀별, 미션별 완료 상태를 브라우저에 저장 |

## 7. 확인받을 점

1. 팀 3개(B2B 영업, 마케팅, 상품기획)와 미션 4개씩, 이 구성이 맞는가?
2. 가상 회사 **대성모션**(제조 B2B, 서보모터)을 그대로 쓸 것인가, 아니면 실제 업종에 맞춰 바꿀 것인가?
3. 강사 기능(수강생 산출물 제출·확인)이 필요한가? 이번 설계는 수강생 혼자 정답 확인까지 하는 **자습형**입니다. 제출 기능은 서버가 필요해 정적 사이트만으로는 어렵습니다.
